# CaseLens

> **SYNTHETIC DATA NOTICE:** every case, person, plate, phone number, and file in this repository is
> fictional and generated by `data_gen/`. No real case data is used, ever.

CaseLens is an evidence-search copilot. Upload a mixed case file (PDFs, audio, video, CSV) and ask questions
in plain English. Answers come back as a cited, auditable timeline: every claim links to its source page,
timestamp, frame, or row, and the system says "insufficient evidence" instead of guessing.

**Status:** Week 5 of 6, Evals + hardening (Week 4 gate passed: full flow in the browser). The demo case ingests end to
end, all four modalities, and the investigator agent answers in plain English with citations (page + bbox,
audio ms, video frame, table row), shows contradictions side by side, and refuses with "insufficient
evidence" when nothing supports an answer. The web app (local dev sign-in for now; Firebase in Week 6)
shows cited answers, opens each citation at the exact page / second / frame / row, and has the timeline,
entity graph, ingest progress and audit views.

## Local development

Requirements: Python 3.11, Node 20+ with pnpm, Docker, and GNU make (on Windows, `mingw32-make` works).

```
make install   # Python venv + web deps
make up        # Postgres 16 + pgvector, MinIO
make migrate   # apply the schema
make test      # all tests
make lint      # ruff, mypy, eslint, tsc
make eval      # smoke eval: 10 gold questions (make eval-full: all 50 + README table)
```

## See it working (ingest the demo case)

After `make install`, `make up` and `make migrate`, copy `.env.example` to `.env` and optionally add a free
Gemini key (`CASELENS_GEMINI_API_KEY`) for name / event extraction and video captions. Then:

```
python -m caselens_data_gen --case riverside_lot          # generate the SYNTHETIC case (~1 min)
python -m caselens_workers submit data_gen/output/riverside_lot --name "The Riverside Lot Homicide"
python -m caselens_workers run --once                     # ingest all 18 files (~10 min on a laptop CPU)
python -m caselens_workers status                         # per-stage job status
python -m caselens_evals.ingest_check                     # compare with the hidden answer key -> GATE: PASS
```

To look at the results, query Postgres (`docker compose exec postgres psql -U caselens -d caselens`), e.g.
the cross-source timeline around the shooting:

```sql
SELECT to_char(t_start AT TIME ZONE 'America/Los_Angeles', 'HH24:MI:SS') AS t, description
FROM events WHERE t_start BETWEEN '2026-03-14 22:38-07' AND '2026-03-14 22:50-07' ORDER BY t_start;
```

Then ask the investigator agent (needs `CASELENS_GEMINI_API_KEY`; ids from the `cases` and `users` tables):

```
python -m caselens_agent ask --case-id <case uuid> --user-id <seed lead uuid> "Who was in the gray sedan on March 14?"
```

## Run the web app (local)

```
# .env needs CASELENS_DEV_AUTH_SECRET (any 32+ char random string) and CASELENS_ENVIRONMENT=local
python -m caselens_api seed-dev-users     # adds analyst + demo viewer, prints dev tokens
#   put them in apps/web/.env.local as VITE_DEV_TOKEN_LEAD / _ANALYST / _VIEWER (gitignored)
python -m caselens_api serve              # API on http://127.0.0.1:8000
cd apps/web && pnpm dev                   # web app on http://127.0.0.1:5173
```

Pick a dev identity on the sign-in screen (lead, analyst, or the read-only demo viewer), open the demo case,
and ask a question.

Contributor and agent rules are in `CLAUDE.md`.

set, run on the free Gemini tier to save quota (see DECISIONS D-064). `make eval-full` runs all 50.

$0.005 per question at paid list prices). Component evals (no LLM): OCR CER 4.5% on the scanned
statement text, ASR WER 3.5% / 4.1%, diarization 100%, entity-resolution precision 100% (recall:
people 80%, places 64%, vehicles 14%).
